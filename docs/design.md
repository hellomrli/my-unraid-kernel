# 官方基础包与替换内核

本项目分开选择系统基础版本和内核版本。官方 Unraid 包提供用户空间与固件，ich777 的最新源码归档提供将要替换的内核。

## 保留与替换的边界

`bzimage` 被替换为重新编译的内核；`bzroot` 中的模块树随新内核打包。`bzmodules` 是挂载到 `/usr` 的用户空间映像，保留官方包的原始字节，并在静态验收中比较。

OpenZFS 针对新内核重建。官方包中的固件和其他基础文件保留，完整 ZIP 重新生成两份引导哈希。

i915 SR-IOV 已独立为插件驱动包，当前内核构建不跟踪或集成该驱动。历史文档仍保留拆分之前的版本记录。

## 编译器与状态

自动检查从官方 `bzimage` 提取 GCC 版本，云构建采用至少 15.3.0 的工具链。官方或 ich777 任一来源变化，都可能产生新的系统与内核组合。

成功发布后才更新上游状态；失败不提前标记为已构建。因此后续定时检查可以重试同一组合。

## 树外模块头文件

保留官方 `bzmodules` 的代价是 `/usr/src/linux-官方版本` 也随官方保留。替换后的内核版本可能不同，使 `/lib/modules/新内核/{build,source}` 链接在 NAS 上缺少匹配目标。

这种情况影响直接在 NAS 上编译 NVIDIA、r8125 等树外模块的插件，不等于内核模块加载失败。需要源码构建时，应取得该内核对应的 ich777 `linux-版本.tar.xz`，放到可写目录，并将 build/source 链接指向完整匹配的源码树。目录和版本应以当前 `uname -r` 为准。

`bzmodules` 因与官方一致不单独随本项目 Release 分发，校验清单仍包含它。使用完整 USB 包或手动核对清单时应理解这一点。
